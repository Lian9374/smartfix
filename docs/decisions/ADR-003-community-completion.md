# ADR-003 — 社区验收规则与通知、审计闭环

- 状态：已接受，作为本次实现与验收基线
- 日期：2026-10-08
- 决策授权：项目使用者明确要求自行完成 A/E 社区衔接，并正式记录原暂定规则；由本次实现选定既有建议基线。不是一次团队会议批准记录。
- 替代：社区实施契约 §1、计划 §29 中 D-05、D-09、D-10、D-13、D-15 的未定状态；旧章节保留为历史。

## 五项结论

1. **D-05：禁止自我采纳。** 提问者仍可回答自己的问题，但不能采纳该回答；服务端和页面均执行此规则。自我回答不发送自我通知。
2. **D-09：不增加独立的关闭回答开关。** 采纳表示已有解决方案，问题可见时仍可继续回答；隐藏或撤回的内容遵循现有可见性权限。
3. **D-10：本 Sprint 社区问题与回答保持纯文本。** 不新增社区附件，不复用报修附件。网站装饰 PNG 和报修照片不受此决策影响。
4. **D-13：保留 V18 的复合外键，并保留服务端归属校验与条件更新。** 采纳答案必须属于该问题；隐藏已采纳答案时清除采纳，恢复答案不会自动重新采纳。
5. **D-15：同一作者在默认两分钟内提交相同标题和正文的问题会被拒绝。** 保留可配置的滚动 24 小时上限：问题、回答分别默认 20 条；不额外叠加 30 秒最小间隔。2026-10-09 起，提问与回答发布通过用户模块公共 API，在同一 READ_COMMITTED 事务中先锁作者账号，再检查计数与插入，保证通过这些发布入口的同账号并发上限；重复问题也在该锁内检查。举报唯一性另由数据库索引保证。直接数据库写入不属于该入口保证。原 `duplicate-detection-enabled=false` 开关仍明确关闭两个发布保护，以保持现有配置契约。

## 完成闭环

- 管理举报提供待处理、已处理、全部视图；处理记录保留决定、处理人、时间、备注，隐藏内容的恢复按钮持续可达。恢复保持原处理决定，不把举报重新放回待处理。
- 通知基础兼容 GitHub main `ee33858d8255b488060b4c476e6ba2c1900d3845`：保留报修及工单监听，新增社区回答、采纳、管理员隐藏监听。通知入口 `/notifications`，仅本人可读与标记已读。
- 社区通知在业务事务成功提交后写入独立事务；回滚不写通知。通知文本不复制敏感内容，隐藏通知不生成公开内容链接。
- 正式审计保存操作人、目标类型与 ID、动作、结果、服务器时间；隐藏、恢复、举报处理在业务事务中落库。失败操作、回滚及无状态变化的重复操作不留下成功审计。
- 审计入口 `/admin/community/audit`，管理员可分页查看；没有网页编辑或删除接口。
- 新增 `V20__create_notifications.sql` 与 `V21__create_audit_entries.sql`，不修改已执行的 V1–V19。升级前仍按数据库指南备份；正常启动由 Flyway 应用增量迁移。

## 边界

当前通知沿用已有 AFTER_COMMIT 同步监听机制；通知写入异常被记录，不回滚已经提交的社区操作。没有持久化 outbox 或自动重试，因此这不是断电、数据库暂时不可用时的保证送达机制。需要可靠重试时另加独立迁移和投递任务。

审计记录不会保存帖子全文、口令或通知正文；举报处理备注仍在举报表中。应用层只追加，具有数据库维护权限的人仍可修改表，未声称具备不可篡改合规审计能力。
