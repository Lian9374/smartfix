# ADR-004：校园地图第一版集成

- 日期：2026-10-08
- 状态：当前分支采用的集成基线
- 后续：真实 NUS 在线底图及建筑状态概览按用户追加要求由 [ADR-005](ADR-005-nus-online-map.md) 扩展；本文件的目录权限和报修规则继续适用。
- 范围：Sprint 3 User D（ZHANG JINGYI）的校园地图；依据开发计划 §14.4、§17.4、N-25、D-11 和 D-16。

## 决定

按 D-11 推荐的选项③实现 `GET /campus-map`：真实设施列表 + 建筑／楼层文字定位。地图不依赖外部 SDK、网络瓦片或坐标，当前数据没有经核实的经纬度，因此不绘制虚构地理位置。页面的折叠地图图标只是装饰。

现有 `Location` 是空间位置，`Facility` 是具体设备。建筑目录来自启用的 `Location`，设施列表来自关联启用地点的 `Facility`。允许建筑存在但尚未登记设施；明确显示空状态，不自动生成设备或状态。已有 V12 设施表即可支持本次集成，无新增迁移。

## 入口和交互

- 申请人、技师、管理员登录后均可从导航和首页进入地图。管理员导航使用现有侧栏。
- 建筑目录、楼层、设施状态和名称搜索可以组合使用。搜索忽略大小写，按文字包含匹配；`%`、`_` 是普通字符。
- 楼层选项由当前建筑的真实地点决定。切换建筑重置楼层和页码，保留搜索与状态；提交筛选重置页码。清除筛选回到校园总览。
- 默认每页 12 条，最多 48 条；按建筑、楼层、设施名称和 ID 稳定排序，越界页码落到有效页。翻页保留筛选条件。
- 顶部总数反映全部启用校园数据；三种状态计数反映建筑、楼层、文字筛选后的区域，应用状态筛选之前计算。
- 申请人的设施卡片提供 `/requests/new?locationId=...`。服务端重新验证地点存在且启用后预选地点；用户仍须填写并提交表单。
- 打开地图、进入报修和提交报修不会自动改变设施状态。管理员现有 `/admin/facilities` 状态修改会反映在地图里。
- 表单和链接由服务端渲染，不依赖 JavaScript；窄屏使用现有导航菜单和单列卡片。

## 地图字段边界（D-16 的局部落实）

地图公开设施名称、建筑、楼层和状态；所有访问者均须拥有有效登录账户。管理员还可在地图查看房间号和完整地点标签。申请人及技师的地图 DTO 不包含房间号，完整 `display_name` 被替换成建筑／楼层标签，以免名称间接泄漏房间。文字搜索也只使用相同的授权 DTO 字段，不能通过搜索精确房间推断设施。

地图不返回实体、设施描述、工单内容、附件、报修人身份、内部备注或 SLA 明细。地点 ID 仅用于现有报修入口，不能作为访问其他受限资源的授权凭证。

这一规则仅针对地图响应，不修改现有报修地点选项和工单访问规则；工单仍由 `RequestAccessService` 授权。开发计划中的 D-16 尚未统一冻结，这是本分支采取的保守地图边界，不代表团队已批准全系统精确位置策略。

## 验证

`CampusMapIntegrationIT` 使用独立 H2 数据库、真实登录、安全过滤器、服务和 Thymeleaf 模板，覆盖角色可见性、受限字段及搜索、停用地点、组合筛选、统计、分页、空数据、输入校验、地图入口、报修地点预选与非法地点拒绝、状态更新与报修不自动改状态。替代原来仅验证视图名称的 `CampusMapControllerTest`。

报修提交测试仅替代现有工单编号计数器：H2 无法执行该计数器的 PostgreSQL `ON CONFLICT` 语句；真实 PostgreSQL 计数器由既有 `RequestWorkflowPostgresIT` 覆盖。地图查询、权限、工单提交服务和设施状态不替代。

可用 `-Dsmartfix.map.ui.export=target/campus-map-ui` 导出测试页面进行真实浏览器视觉检查；这些合成数据只存在于测试数据库，不会写入应用数据库。后续若需要真实地理平面图、坐标或室内导航，应另行确认数据来源和 ADR。
