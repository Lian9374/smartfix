# Sprint 4 UserD：地图、设施、报表与公告质量收口

日期：2026-10-13。分支：`feature/sprint4-userd-map-reporting`，基于 UserC 的 `4c61b88`。本包按 [Sprint 4 计划](SmartFix_Sprint4_Development_Plan_CN.md) 的 D-01 至 D-04 实施，不包含 AWS、SLA 策略或通知投递改造。

## 页面和业务行为

- `/campus-map`：保留真实 NUS 建筑目录、OneMap 底图和真实业务状态。底图／地图库失败提示独立保存，切换校区、清空搜索或搜索无匹配建筑后仍可见；文字目录和状态继续可用。地图库和瓦片来源不代表数据覆盖全部建筑，也不代表故障来自外部实时传感器。
- `/admin/facilities`：保留人工设施状态管理、确认和成功反馈；列表一次加载关联地点，消除展示地点名称时的追加查询。状态不会因单条报修自动改变。
- `/admin/reports`：复用共享标题卡片、指标卡片及响应式表单，增加日期范围错误定位和明确空状态。无效日期不生成报表或导出链接；直接导出倒置范围返回 400。统计仍以新加坡日期、工单创建时间的半开区间为准。
- `/admin/announcements`：统一输入间距、移动端宽度、提交中反馈、内容字符计数和字段错误关联；明确日期为 Singapore UTC+8。发布／撤回使用现有确认机制，创建／发布／撤回显示服务端成功反馈。
- `/announcements`：仅展示已发布且处于有效时间范围的公告。真实浏览器验证发布后出现、撤回后消失；没有使用静态展示代替接口。

所有管理页面仍由既有服务端 `/admin/**` 角色保护和 CSRF 保护约束；地图沿用有效账号校验、不同角色私有地点信息过滤及文字访问路径。本包未新增身份系统、角色、业务状态或认证绕过。

## 性能改进和实测

### 地图数据库读取

旧地图状态统计读取完整设施及地点，再在 Java 中按建筑／状态分组。新查询仅读取 `locationId / status / count`，数据库先按地点／状态聚合，再按既有目录映射到建筑。未匹配地点仍计入 unmapped；停用地点不进入统计。

`CampusMapIntegrationIT` 及真实 PostgreSQL 的 `CampusMapPostgresIT` 使用同一组断言：123 条有效设施，旧查询 1 次、加载 125 个实体；新查询 1 次、加载 0 个设施／地点实体，数量一致。含停用地点的管理员设施列表 124 条，只查询一次。这里优化的是返回数据和实体加载量，不声称地图原来存在逐设施 SQL 查询。

[数据库测量数据](evidence/userd/roles/query-measurements.json) 使用独立 PostgreSQL 16 验收库，在回滚事务中加入 600 条设施、12 个地点。旧形状读取返回 600 行，分组读取返回 36 行。交替执行一次预热及五次采样，服务器执行时间中位数分别为 **0.886 ms / 0.463 ms**。该比较仅是 `EXPLAIN ANALYZE` 数据库执行时间，不包含实体加载、网络或浏览器耗时，也不是生产容量承诺。

可复现命令：给 `ROLE_ACCEPTANCE_DB_URL` 设置专用本机 `smartfix_role_acceptance_test` 库，并提供 `TEST_DB_USERNAME / TEST_DB_PASSWORD`，执行 `node tools/measure-userd-queries.mjs`。脚本强制限制测试库、设置语句超时，并执行 `ROLLBACK`，不保留性能夹具。

### 报表和页面

报表原来收集全部 DTO，再多次扫描。现在每页最多 100 个 DTO，单次扫描累计数量、类别、实际优先级、状态和解决时间，保留既有均值及 CSV 字段。跨页测试用 100 条一小时、1 条两小时记录确认加权均值为 `102/101` 小时；空数据为有限的零值。

这不是完整的有界内存承诺：现有 RequestReadService 仍返回分页实体，事务持久化上下文和每页总数查询仍可能有额外成本。没有凭空更改查询契约、限制可选报表日期或添加性能索引。

[端点测量数据](evidence/userd/roles/endpoint-measurements.json) 记录报表、CSV、地图页面／状态、设施列表及公告列表每个端点五次顺序请求的实际时间、字节数和 HTTP 状态。数据环境为已迁移的建筑目录及少量验收公告，不是大量真实工单压测。测量时没有包含用户业务数据或私有内容。

地图既有单次 pending 保护、10 秒超时、30 秒更新、后台暂停以及登录失效停更继续保留。设施筛选目前仍在服务内读取候选后分页，公告管理列表仍未分页；这两个现有契约未在本包擅自改变。更大部署规模需要另行用实际负载验证并决定服务端分页。本轮没有足够证据新增索引，因此迁移文件没有改动，最高版本仍为 V25。

## SLA 和模块边界

当前报表不依赖 SLA 截止时间或 SLA 合规数据。页面明确说明：解决率是工单状态比例，不是期限合规率。UserE 完成真实只读 SLA 契约后，再按文档需要集成；本轮不填写假期限、假合规率或补入旧 V13 迁移。

地图测试仍触发已知的 `NotificationEventListener` 初始状态事件 NPE 日志；业务事务与地图测试不因此失败。该通知消费者问题属于 E，并不被本包的通过记录标为已修复。

## 实际验证与证据

最终统计及源码／构建指纹见 [验证摘要](evidence/userd/verification-summary.json)，页面记录见 [浏览器结果](evidence/userd/roles/results-layout.json)。

- 相关模块回归：48 个单元测试、23 个 H2 地图集成测试，零失败／错误。
- 原生 PostgreSQL：10 个控制器单元测试、24 个集成测试（23 个地图合同及 1 个目录迁移测试），零失败／错误。真实 Flyway 及 Hibernate validate 开启。
- 最后表单排列调整：重新运行 10 个控制器测试并构建成功；地图数据库逻辑未再次改变。这些计数存在重复，不相加作为独立测试总数。
- 浏览器使用独立 PostgreSQL、临时应用和 Edge，覆盖 1440 / 1000 / 768 / 390 / 320 像素宽度、唯一 HTML ID、单主标题、无横向溢出、实际键盘操作、报表错误／空状态／CSV、地图库失败及公告创建→发布→撤回。
- `node tools/verify-map-fallback.mjs` 离线 DOM 回归通过；修改过的 JavaScript 语法检查、`git diff --check` 及离线编译结果见摘要。

最终截图人工检查报表、公告表单和地图文字降级布局。它们是桌面浏览器模拟宽度，不代替真机、读屏或生产网络验收。用户业务库、8080 服务和上传目录未修改。

首次测试用例误继承 H2 驱动，已通过测试专用 DynamicPropertySource 指定 PostgreSQL 驱动及方言；没有改变生产认证或 Flyway 校验来绕过测试。临时数据库最初的高端口属于 Windows 保留区间，改用 15444 后正常运行，没有调整系统保留端口配置。
