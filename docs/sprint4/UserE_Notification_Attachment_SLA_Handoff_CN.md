# Sprint 4 UserE 交付记录

日期：2026-10-13。分支：`feature/sprint4-usere-delivery-reliability`，基于 UserD。按用户要求缩短最后验收，不再扩展范围。

## 已实现

- **可靠通知**：报修状态、工单完成、社区回答／采纳／隐藏事件在业务事务内暂存 delivery_tasks，提交后才投递。后台扫描、有限重试、失败状态、稳定去重和管理员重试入口已实现。修复初始 fromStatus=null；正常事件优先使用 C 的 historyId，旧事件使用状态／时刻兼容键，不编造 ID。保留自我回答不通知、恢复／撤回不增加隐藏通知等既有规则。
- **投递工作台 `/admin/delivery`**：分页查看状态、次数、下次尝试及脱敏错误；FAILED／SKIPPED 可确认后重试，已投递任务禁止重试。管理员维护现有账号的可选业务邮箱。地址修改、重试与失败耗尽使用真实 audit_entries；系统动作 actor=NULL，不伪造管理员身份，页面显示 Automated system。
- **业务邮件**：默认关闭，仅发送到管理员明确配置的既有账号地址；无有效地址为 SKIPPED，不猜用户名对应邮箱。纯文本通用通知、稳定 Message-ID、5 秒连接／读取／写入超时。默认初次＋三次重试（最多四次），退避 1／5／30 秒；达到上限为 FAILED。人工重试开启新的有限周期并留审计。秘密来自环境，SMTP 健康检查默认关闭，不让可选邮件使基础健康检查失败。
- **SLA `/admin/sla`**：配置实际优先级、RECEIPT／ASSIGNMENT／RESOLUTION／CONFIRMATION 阶段、分钟时长和提醒窗口。无预置生产期限或启用策略。按自然时间计时，既有改派 UNDER_REVIEW／ON_HOLD 暂停解决计时，恢复后扣除暂停时间，REOPENED 重计解决周期。临期／超期通知有效管理员，并发扫描和重复事件幂等，不改变工单状态机。
- **D 只读契约**：`GET /admin/sla/requests/{id}` 返回 UNCONFIGURED／AVAILABLE 及真实阶段快照；报表链接到 SLA 工作台，不把解决率当作合规率。
- **附件**：`.part` 写入、实际输入大小限制、完成后移动及中途失败清理；元数据确定回滚清理新文件。不确定提交保留文件，避免删掉可能已经提交的照片。沿用父工单资源授权，并拒绝读取符号链接。
- **只读附件核对 `/admin/attachments/inspection`**：报告超过 24 小时且无引用的生成文件键，最多扫描 10000 个目录项。不在线自动删除；崩溃后须停用上传、备份、重新核对再维护。

管理接口保留后端 ADMINISTRATOR、有效账号、强制密码设置和 CSRF 检查。普通注册不增加邮箱、角色或提权字段。新增邮箱不用于认证、验证、邀请或密码恢复。

## 规则依据和选择

SLA 自然时间、created_at 起点、改派暂停、重开重计时及 ADMIN 升级来自 Sprint 3 §14.8 建议基线。**所有初始阶段包括确认均以请求创建时刻计算**；确认阶段在解决时建立，可能立即到期。生产规则若应从解决时刻计算确认期限，需先改规则及测试。

时长和提醒窗口必须管理员输入。已有计时器保留创建时的有效优先级和时长快照；后来优先级或策略变更不自动改期。重开解决周期使用当前策略。临期通知采用与升级相同的管理员受众，是补齐文档空缺的最小选择。

Sprint 3 §14.7 的“三次重试”明确为初次＋三次，默认 1／5／30 秒；技术参数可配置。最终原生测试使用三次总尝试，是测试值。原账号无邮箱，因此只在 users 加可选 notification_email，由管理员维护，不增加平行身份系统。

## 事务与可靠性边界

BEFORE_COMMIT 仅落库投递意图，不发送 SMTP；AFTER_COMMIT 唤醒及定时扫描才投递。PostgreSQL 使用唯一键与 ON CONFLICT，不额外锁其他用户账号，避免互相回答时形成跨账号锁顺序。H2 测试使用仅插入 MERGE。

worker 独立事务锁定任务；站内通知沿用 dedup_key。SMTP 没有通用恰好一次保证：服务器接收后进程崩溃／确认丢失，重试可能重复，稳定 Message-ID 只是辅助。数据库不可用或发送与记账之间崩溃时，外部发送次数不一定等于数据库计数。

outbox 写入失败会使共享业务事务失败，不能丢失投递意图后声称成功；提交后的发送故障不回滚业务。历史事件不自动回填，新的去重格式不追溯修复历史通知。
