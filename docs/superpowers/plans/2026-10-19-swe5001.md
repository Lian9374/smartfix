# SWE5001 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax.

**Goal:** Deliver a running distributed SmartFix MVP and reproducible cloud/deployment/scaling tooling.
**Architecture:** Existing Java Core publishes a transactional notification outbox to SQS. Independent Python Worker owns its inbox and calls a protected Core projection API. Shared sessions and uploads permit horizontal Core replicas.
**Tech Stack:** Java 21, Spring Boot, Python 3.12, PostgreSQL 16, SQS, nginx, Prometheus, k6, AWS ECS Fargate, CloudFormation, GitHub Actions.
**Spec:** docs/superpowers/specs/2026-10-19-swe5001-design.md

## Global Constraints
- Preserve main and the SWE5006 baseline. Branch swe5001-cloud-native.
- Do not create paid resources or alter existing shared infrastructure.
- Keep existing workflow/UI and Java 21 compatibility. No Kubernetes.
- Real tests/measurements only; report local and cloud status separately.

## Review Focus
- SQS duplicate after publish/database commit gap: no duplicate notification.
- Worker crash after Core callback: redelivery completes safely.
- Invalid token, mismatched dedup key and poison payloads: reject without completing task.
- Concurrent replicas: outbox row locks and inbox locks prevent conflicting writes.
- Login and uploads survive switching Core instances; no public internal callback.
