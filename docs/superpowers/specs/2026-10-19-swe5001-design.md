# SWE5001 SmartFix distributed notification MVP

## Intent and baseline
The user requests finished code and a full implementation process on a new branch in Lian9374/smartfix. Preserve SWE5006 main at 6cb329f4fe9b1f7e2e708b9ee00d81c456740fc0. Implement directly in the isolated clone, without provisioning paid infrastructure. This implements the supplied MVP strategy, not the original four-service proposal.

## Audit
Reusable: Java 21 / Spring Boot 3.5.4 MVC application; maintenance, dispatch, work orders, authentication, notifications; Flyway V1–V27; transactional delivery_tasks outbox; retry/admin UI; SMTP; Maven tests; Dockerfile; Compose; Jenkins build/test pipeline.
Missing: independent process, managed queue, independent delivery data, shared sessions/uploads, cloud infrastructure, deployment pipeline, repeatable scaling measurement, evidence.
Alternatives: full four-way domain extraction is too risky before 24 October; only moving a scheduler to another JVM shares all domain persistence and is a weak service boundary. Select an independently built Python notification worker with its own PostgreSQL database and SQS contract.

## Boundaries and flow
Core owns identity, request/dispatch/work order transactions, delivery intent/outbox, notification read model and session data. Worker owns idempotency/inbox and delivery execution. Worker has no Core database credentials. Core has no Worker database credentials. Local PostgreSQL uses two containers; AWS uses two databases/users in one private RDS instance as a cost-conscious MVP (not independent physical failure domains).
Existing BEFORE_COMMIT listeners continue inserting delivery_tasks. Distributed profile disables legacy eager delivery/scheduler. A Core relay locks due rows with SKIP LOCKED, publishes notification.requested.v1 JSON to SQS, and marks QUEUED in the same database transaction. Send/commit gap can duplicate; stable task id and dedup key identify the logical delivery. A callback is accepted even if the relay transaction has rolled back to PENDING. Worker persists an event plus payload hash, executes delivery, calls Core, marks complete, then deletes SQS message. A crash after callback replays safely using Core idempotency; a crash after SMTP can duplicate email (explicit limitation). Queue failures leave rows pending with bounded backoff; poison messages reach DLQ after five receives. No ordering guarantee is required across independent notifications. No exactly-once claim.

## Contract
Envelope fields: schemaVersion=1, eventType=notification.requested.v1, taskId positive integer, dedupKey nonempty <=200, recipientId positive integer, channel IN_APP|EMAIL, notificationType <=80, title <=150, message <=1000, referenceId nullable integer, email nullable string, occurredAt ISO8601 UTC. No credentials in messages. Callback POST /internal/deliveries/{taskId}/complete accepts dedupKey and outcome DELIVERED|SKIPPED; Core loads original task and derives notification content, never trusting callback content. Dedicated stateless bearer-token filter, constant-time comparison, minimum 32-character token. Public ALB blocks /internal/*; worker callback uses private service discovery. Token in Secrets Manager, no long-lived AWS keys.

## Runtime and scaling
Core containers run Java 21; Worker Python 3.12. Local Compose: Core replicas behind nginx, separate databases, SQS emulator, worker, Prometheus. Spring Session JDBC only in distributed profile; shared named upload volume locally and EFS in AWS. Existing LocalAttachmentStorageService is reused. Keep SLA scheduler in Core with existing per-state locks and idempotency. Metrics: relay published/failures/backlog, worker processed/failures, HTTP timing, process CPU/memory; SQS queue backlog and ECS Container Insights in AWS.
AWS: VPC public ALB/ECS subnets, private database subnets, ECS Fargate services, ECR, RDS PostgreSQL encrypted, EFS encrypted, SQS+DLQ encrypted, CloudWatch logs/alarms/dashboard, IAM task roles restricted to queue and secrets. Public task IPs allow outbound AWS access without NAT charges; security groups admit only ALB/private task traffic. HTTPS requires supplied ACM certificate; no public HTTP application login. CloudFormation template plus shell scripts; provisioning requires explicit cost approval.

## Verification and evidence
Run original Maven suite and new Java tests; Python unit and real PostgreSQL/SQS integration tests; Compose end-to-end requester -> admin -> technician -> async notification; k6 single versus multiple Core replicas behind nginx; record raw summaries and sampled CPU/memory/queue depth. Never invent measurements or equate local validation with AWS deployment. Provide CI build/test/image publish/deploy/smoke and Chinese runbook with remaining manual AWS/account inputs, cost range and teardown.

## Main risks
Database can limit horizontal scaling; JDBC sessions add writes. SMTP side effects are at least once. Queue retention is finite and DLQ requires operator replay. Core callback is a deliberate dependency on Core availability; SQS retries bridge temporary outages. Shared RDS and EFS are MVP tradeoffs. New branch publication must not alter main or enable automatic cloud spending.
