# 第九阶段：正式实验前固定方案

日期：2026-10-29。仅实验设计、脚本、观测和低量 smoke。阶段8的19101完整人工验收已由用户明确确认。

质量目标与完整参数以同目录 PLAN.json 为唯一机器可读来源。业务迭代 p95≤1秒、p99≤2秒；端点完整调用 p95≤0.8秒、p99≤1.5秒；业务错误率≤0.5%；内容/认证错误、dropped iterations 必须为0；实际发起率至少达到目标99%。这些是本项目预设工程目标，不能声称老师已经认可。正式实验失败时保留失败，不降低阈值。

成功业务吞吐只计完成内容校验的业务迭代。API回答必须再读取自己的回答并精确匹配answerId、questionId和正文；页面回答必须保留CSRF和会话命令键，经真实POST/重定向显示新正文；维修提交必须出现真实SF工单地址及正文。列表逐页核对预先读取的20个真实ID；搜索固定语料，详情核对ID/标题/回答。登录页、400/403/409/限流、500、超时、驱动错误、内容错误都不计成功。重定向GET单独加入HTTP请求数；延迟按整个调用（含正文与重定向）记录，不与迭代数混用。未请求静态资源，因此这是服务端页面链路，不是浏览器渲染性能。

负载驱动采用单调时钟绝对到达时间，线程池外通过非阻塞信号量决定是否接纳，不排队等空闲线程。工作线程慢、用户会话忙或调度落后都如实记录；不在恢复后突发补发。每轮记录计划数、发起数、完成数、成功数、实际HTTP数、实际速率、错误分类、p95/p99、调度延迟、CPU秒和应用体积字节。NIC和宿主机CPU/进程内存另行采集。令牌由私有本地测试签名器持续生成，保留RS256/30秒有效期/角色/受众；没有关闭身份校验。页面登录在测量窗口外准备，实际业务仍经过Session、账号检查、CSRF与Core到Community认证。

正式同压力组：1/2/3社区实例，各5和20业务迭代/秒，分别API与Core页面路径。容量组：5/10/20/40/80/160逐级独立测试，不认为更高档一定通过；最大持续容量是三次重复均满足同一目标的最高档，不能挑单次最好结果。混合组：独立维修到达流固定2迭代/秒，社区0/5/20/40；维修p95相对维修独立基线恶化≤20%。单热门问题单独测5迭代/秒，不能把锁竞争结果混进普通分布。顺序三次分别1→2→3、3→1→2、2→3→1；每轮60秒预热、300秒测量、最多30秒事件排空。

固定语料为阶段8当时快照加1000合成账号、10000问题、30000回答。合成历史时间固定2026年1月，与当前发帖窗口分离。原有社区配额、重复内容、用户/问题数据库锁全部保留，写入内容每次唯一。账号轮次错位，避免同一批账号永久只执行写动作；混合组社区900人、维修另100人，不争用同一Cookie。阶段9已生成私有完整快照，正式每轮用它恢复到新数据库；旧数据库和附件目录归档保留，不就地清空。先完成快照恢复及相同预热再比较。数据准备或快照恢复耗时不计为业务吞吐。

Core固定1实例；每JVM Xms128m/Xmx384m、G1、ActiveProcessorCount=2、Tomcat40线程、Hikari5连接。Community用同一JAR，在同一轮只改副本数。PG16容器2CPU/1GiB，shared_buffers128MiB/max_connections60。ActiveProcessorCount只告知JVM可见CPU，不是Windows进程CPU配额；社区总可用资源随副本增加，单实例和总资源均须报告。单机共享CPU、Docker虚拟机、磁盘和网卡，其他保留环境不得为凑结果强停；正式报告记录后台负载。此方案验证本地水平扩展，不证明云端多主机能力。垂直扩展、自动扩缩容、AWS没有实施或测试。

观测每15秒采样并记录实际采集时长/时间戳：Core和每个社区的CPU、GC、内存、线程、Tomcat、Hikari活跃/空闲/等待/超时、HTTP计数；PostgreSQL语句指纹/耗时/块命中、锁与等待、连接、事务、IO时间/读写、DB容器CPU/内存/块IO；LB各真实实例计数和耗时；outbox待处理/失败/租约/最旧年龄/尝试数，以及本轮事件到Core收件箱和通知可见时间。原始正文/SQL文本不导出到报告。累计指标按相邻样本做差；没有注册的GC等指标明确标记，不假装为0。观测丢失、发生器CPU>70%单核或p99调度延迟>50ms时，本轮不能用于容量认证。

perf9_suite.py提供正式矩阵和每个有界run的准备/预热/并行混合流/观测/保存。第9阶段只能 --list；--execute还检查私有阶段10状态。结果默认capacityAccepted=false，需要第10阶段结合采样、事件延迟、维修独立基线及全部重复作最终分析，不能只凭HTTP阈值自动认证。第10阶段计算Qn、Sn=Qn/Q1、En=Qn/(n×Q1)，所有档次、失败与波动都保留。尚未运行正式矩阵，不存在本阶段扩容收益结论。
